# ADR-007: Catalog read HTTP for shipping product snapshots

## Status

Accepted

## Date

2026-07-26

## Context

`ShippingServiceImpl.getShippingQuote` uses `PricingService`, `Product` entities, and in-process catalog services to build `ShippingProduct` lists and package details. Wave 4 extracts catalog read paths partially. Wave 5 cannot keep catalog JPA coupling inside integration-service.

## Decision

`ShippingOrchestrator` fetches **`ShippingProductSnapshot`** (subset of `ProductSnapshot` from Onda 3/4) via HTTP from **catalog-service read API** using `wave5.catalog-service.base-url`. Monolith BFF may pre-assemble snapshots for `OrderShippingApi` or integration-service may call catalog directly — default: **integration-service calls catalog** to keep quote logic centralized.

If catalog read is unavailable, apply **GAP-INT-01** fallback (default weight/dimensions with WARN log) — ponytail: naive heuristic; upgrade path is mandatory catalog contract.

## Alternatives considered

### Alternative 1: BFF always passes full product payloads in quote request

- **Pros:** integration-service needs no catalog client.
- **Cons:** Duplicates assembly in BFF and any future cart-service; larger requests.
- **Rejected for default:** Optional optimization later.

### Alternative 2: Keep PricingService in monolith only; integration receives pre-priced packages

- **Pros:** No catalog HTTP in integration.
- **Cons:** Splits packaging logic across services; harder to test quotes in isolation.
- **Rejected.**

### Alternative 3: Defer Wave 5 until full catalog extraction

- **Pros:** Richer catalog API.
- **Cons:** Delays cycle break; master plan allows Wave 4 read-first.
- **Rejected:** Onda 4 partial is explicit prerequisite, not full catalog.

## Consequences

### Positive

- Shipping orchestration decoupled from catalog JPA.
- Validates cross-service read pattern before Wave 6.

### Negative

- Hard dependency on Onda 4 partial gate.
- Fallback heuristic may produce inaccurate quotes — document and monitor.
