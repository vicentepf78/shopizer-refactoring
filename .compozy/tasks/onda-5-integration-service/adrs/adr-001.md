# ADR-001: Single Compozy workflow for integration-service in Wave 5

## Status

Accepted

## Date

2026-07-26

## Context

Wave 5 extracts payment and shipping orchestration into one deployable `integration-service`. Both domains share the Strangler BFF, plugin registry wiring, shared DB configuration tables, and the same prerequisite gates (Onda 3 contracts, Onda 4 catalog read). TLC artifacts in `.specs/features/onda-5-integration-service/` define a single feature with PAY/SHP/STR requirement IDs and 38 atomic tasks.

## Decision

Treat Wave 5 as **one Compozy workflow** (`onda-5-integration-service`) producing one PRD, one TechSpec, and a task set covering `integration-service`, `sm-integration-core`, and Strangler changes in `sm-shop`. TLC in `.specs/` is the authoritative product and technical source; Compozy artifacts translate without scope change. Execute remains **blocked until Onda 3 + Onda 4 partial** complete.

## Alternatives considered

### Alternative 1: Separate payment-service and shipping-service workflows

- **Pros:** Smaller documents; independent deploy cadence.
- **Cons:** Duplicates Strangler config, Pact setup, shared module registry, and Wave5 properties; shipping and payment admin UIs share integration configuration patterns.
- **Rejected:** Cost of duplicated governance exceeds benefit for tightly related generic subdomains.

### Alternative 2: Defer Wave 5 until full Order extraction

- **Pros:** Avoids partial cycle break.
- **Cons:** Blocks Wave 6; master plan places integration at week 49–56 specifically to break payment coupling before order split.
- **Rejected:** Stateless payment boundary is the enabler for Wave 6.

### Alternative 3: Start Execute before Onda 3 contracts exist

- **Pros:** Calendar progress.
- **Cons:** `PaymentModuleV2` and checkout saga are hard prerequisites; early code would rework contracts.
- **Rejected:** Explicit gate in master plan and PRD.

## Consequences

### Positive

- One backlog, one strangler profile, one pact gate for integration domain.
- Aligns with Waves 1–2 precedent (single workflow per wave tranche).

### Negative

- Larger PRD/TechSpec than a single-capability feature.
- Parallel payment/shipping tracks need milestone discipline (P-ready, S-ready).

### Risks

- Scope creep into order service — mitigated by ADR-002 and non-goals.
