# ADR-007: ShoppingCart extraction before Order cutover

## Status

Accepted

## Date

2026-07-26

## Context

Shopping cart (difficulty 7/10) and order (9/10) are coupled via `ShoppingCartCalculationServiceImpl` → `OrderService.calculateShoppingCartTotal`. Extracting order first leaves cart calling remote order while cart data still local — workable. Extracting cart first requires **totals API** on order boundary before cart strangler cutover.

## Decision

Phased cutover sequence:

1. **TOT-ready** — Deploy totals HTTP API (monolith or order-service); switch calculation client
2. **SC-ready** — `shoppingcart-service` CRUD remote; strangler flag
3. **OR-read-ready** — order-service read paths remote
4. **CHK-ready** — saga checkout enabled last

Cart strangler supports **shadow mode** (TLC T14): compare remote vs in-process reads before write cutover.

Order write/commit never goes remote until saga path is green in staging.

## Alternatives considered

### Big-bang cart + order + checkout

- **Pros:** Single cutover event.
- **Cons:** Unacceptable rollback surface; violates master plan incremental principle.
- **Rejected.**

### Order before cart

- **Pros:** Hub domain first.
- **Cons:** Cart still cycles to in-process OrderService until cart extracted; partial cycle remains longer.
- **Rejected** — totals API needs order boundary first, but cart cutover before saga is lower risk.

### Cart only, defer order indefinitely

- **Pros:** Minimal scope.
- **Cons:** Wave 6 incomplete; checkout remains monolith.
- **Rejected** — out of scope for this wave.

## Consequences

**Positive:** Incremental validation; cart issues isolated before revenue path; clear milestones.

**Negative:** Longer calendar; multiple flag toggles — mitigated with runbooks (ADR-008).
