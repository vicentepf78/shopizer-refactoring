# ADR-007: Extração ShoppingCart antes de Order cutover

## Status

Aceito

## Data

2026-07-26

## Contexto

Shopping cart (dificuldade 7/10) e order (9/10) estão acoplados via `ShoppingCartCalculationServiceImpl` → `OrderService.calculateShoppingCartTotal`. Extrair order primeiro deixa cart chamando order remoto enquanto dados cart ainda locais — viável. Extrair cart primeiro exige **API totals** na fronteira order antes do cutover strangler do cart.

## Decisão

Sequência de cutover faseado:

1. **TOT-ready** — Implantar API totals HTTP (monólito ou order-service); alternar client de cálculo
2. **SC-ready** — `shoppingcart-service` CRUD remoto; flag strangler
3. **OR-read-ready** — caminhos read order-service remotos
4. **CHK-ready** — saga checkout habilitada por último

Strangler cart suporta **shadow mode** (TLC T14): comparar leituras remoto vs in-process antes do cutover de escrita.

Write/commit de order nunca vai remoto até caminho saga verde em staging.

## Alternativas consideradas

### Big-bang cart + order + checkout

- **Prós:** Evento único de cutover.
- **Contras:** Superfície de rollback inaceitável; viola princípio incremental do plano mestre.
- **Rejeitada.**

### Order antes de cart

- **Prós:** Domínio hub primeiro.
- **Contras:** Cart ainda cicla para OrderService in-process até cart extraído; ciclo parcial permanece mais tempo.
- **Rejeitada** — API totals precisa fronteira order primeiro, mas cutover cart antes da saga é menor risco.

### Somente cart, adiar order indefinidamente

- **Prós:** Escopo mínimo.
- **Contras:** Onda 6 incompleta; checkout permanece monólito.
- **Rejeitada** — fora de escopo desta onda.

## Consequências

**Positivas:** Validação incremental; issues de cart isoladas antes do caminho de receita; marcos claros.

**Negativas:** Calendário mais longo; múltiplas alternâncias de flag — mitigado com runbooks (ADR-008).
