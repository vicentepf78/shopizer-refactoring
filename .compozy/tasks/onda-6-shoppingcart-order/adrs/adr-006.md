# ADR-006: Cálculo de tax no BFF — remoto em order-service adiado

## Status

Aceito

## Data

2026-07-26

## Contexto

`OrderServiceImpl` usa `TaxService` in-process para `calculateShoppingCartTotal` e `processOrder`. `tax-service` (Onda 1) trata **CRUD admin** de classes/alíquotas de tax. Cálculo de tax no checkout pode permanecer no monólito ou ir remoto durante a Onda 6.

Mover tax para `order-service` adiciona outra dependência durante a saga de maior risco e duplica contexto de endereço/produto já montado no checkout BFF.

## Decisão

Para **Execute da Onda 6**:

- **Cálculo de tax invocado de `CheckoutApplicationService`** via HTTP para `tax-service` (ou tax core in-process se strangler tax ainda não ativo — preferir HTTP conforme padrão Onda 1)
- **`OrderSnapshot.taxItems`** carrega linhas de tax pré-computadas para endpoint commit `order-service`
- **`order-service` NÃO DEVE** chamar `TaxService` ou `tax-service` durante commit ou cálculo de totals

**Caminho de upgrade (pós-Onda 6):** Flag opcional `wave6.tax.remote-in-order-service` para mover lógica tax de totals para order-service se latência BFF inaceitável — exige novo ADR.

## Alternativas consideradas

### Tax totalmente em order-service

- **Prós:** Order dono de toda lógica de totals.
- **Contras:** order-service precisa endereço de frete, snapshots tax class de produto; hops HTTP extras do cart; maior complexidade saga.
- **Rejeitada na Onda 6.**

### Tax permanece somente in-process sm-core

- **Prós:** Zero mudança.
- **Contras:** Bloqueia extração order-service para endpoint totals.
- **Rejeitada** — totals devem estar em order-service (quebra de ciclo).

### JAR tax-library compartilhado

- **Prós:** Sem rede.
- **Contras:** Acopla order-service a JAR de regras tax; viola objetivo de extração.
- **Rejeitada.**

## Consequências

**Positivas:** order-service menor; BFF já tem contexto checkout; tax-service reutilizado.

**Negativas:** BFF deve acompanhar mudanças de regras tax; ponto único para bugs tax no checkout.
