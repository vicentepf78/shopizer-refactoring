# ADR-004: Transactional outbox for order domain events

## Status

Accepted

## Date

2026-07-26

## Context

After saga commit, downstream actions (email templates, inventory adjustment, analytics) must not use in-process Spring events that fail silently on service restart. Cross-service notification requires reliable delivery without dual-write anomalies.

## Decision

Implement **transactional outbox** in `order-service`:

- Table `ORDER_OUTBOX` in shared MySQL
- Insert outbox row in **same transaction** as order persist
- In-process `@Scheduled` relay (default) publishes to `ApplicationEventPublisher` / future message bus
- Event types: `OrderPlaced`, `OrderPaid`, `OrderCancelled`

Relay upgrade path: extract to standalone worker without schema change.

## Alternatives considered

### Change Data Capture (Debezium)

- **Pros:** No application relay code.
- **Cons:** Infra complexity; not in current stack.
- **Deferred.**

### Fire-and-forget async after commit

- **Pros:** Simple.
- **Cons:** Lost events on crash between commit and publish.
- **Rejected.**

### Dual-write to message queue

- **Pros:** Fast publish.
- **Cons:** Inconsistent if queue write fails after DB commit.
- **Rejected.**

## Consequences

**Positive:** At-least-once delivery; audit trail; aligns with Onda 3 outbox PoC.

**Negative:** Relay lag; monitor outbox depth (alert > 100 pending).

## Implementation notes

- `published_at IS NULL` rows polled every 5s (configurable)
- DLQ after 10 failures — manual replay script in runbook
