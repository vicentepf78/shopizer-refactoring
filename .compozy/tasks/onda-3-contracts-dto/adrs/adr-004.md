# ADR-004: Parallel PaymentModuleV2 / ShippingQuoteModuleV2 with legacy adapter bridge

## Status

Accepted

## Date

2026-07-26

## Context

`PaymentModule` and `ShippingQuoteModule` in `sm-core-modules` accept JPA entities (`Order`, `Customer`, `MerchantStore`, `ShoppingCartItem`, `Delivery`, etc.). This is MODEL coupling disguised as a plugin API (master plan §6.7). Wave 5 integration-service extraction requires DTO-only contracts.

Existing plugins (Stripe, PayPal, USPS, etc.) implement the legacy interface and ship as compiled classes in `sm-core`. Breaking binary compatibility would force rewriting all integrations in Wave 3 — out of scope.

## Decision

1. Add **integration DTOs** in `sm-core-modules` (e.g. `PaymentRequestContext`, `PaymentCaptureContext`, `ShippingQuoteRequestContext`, `IntegrationStoreContext`) — no JPA types.
2. Introduce **`PaymentModuleV2`** and **`ShippingQuoteModuleV2`** interfaces using only DTOs + existing `IntegrationConfiguration` / `IntegrationModule` types.
3. **`PaymentServiceImpl` / `ShippingServiceImpl`** detect V2-capable plugins via `instanceof` or optional registry flag; otherwise **adapt** entity graph → DTO → call V2, or delegate to legacy `PaymentModule` methods.
4. **No plugin rewrites required** in Wave 3; provide **reference adapter** `LegacyPaymentModuleBridge` that implements V2 by delegating to V1 (for testing).
5. Wave 5 moves plugins to remote process; Wave 3 only proves DTO path works in-process.

## Alternatives considered

### Alternative 1: Change PaymentModule in place

- **Rejected:** Breaks all plugins; high risk.

### Alternative 2: New module `sm-integration-contracts` separate from sm-core-modules

- **Rejected:** YAGNI — extend existing publishable `sm-core-modules` JAR.

### Alternative 3: JSON-only plugin API

- **Rejected:** Over-engineering for Wave 3; Java interfaces match existing registry pattern.

## Consequences

### Positive

- Clear extraction boundary for Wave 5.
- Legacy plugins untouched.
- DTO mapping centralized in service layer once.

### Negative

- Two interface hierarchies until legacy deprecated.
- Adapter mapping code must stay in sync with entity model changes.

## Implementation notes

- DTOs use `MerchantStoreId` / money as `BigDecimal` / IDs not entity refs.
- `validateModuleConfiguration` accepts `IntegrationStoreContext` in V2.
