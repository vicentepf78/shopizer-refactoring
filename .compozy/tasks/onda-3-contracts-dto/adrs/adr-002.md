# ADR-002: ProductSnapshot supersedes ProductIndexPayload with schema evolution

## Status

Accepted

## Date

2026-07-26

## Context

Wave 2 introduced `ProductIndexPayload` (AD-009) as an interim index DTO so `search-service` could run without JPA. Design OQ-06 deferred `SearchItem` migration to Wave 3. The master plan lists `ProductSnapshot` as a Wave 3 deliverable for search, catalog read, and cross-service reads.

`ProductIndexPayload` uses loose `Map<String,String>` for variants/inventory. A richer `ProductSnapshot` can serve search indexing, future catalog-read APIs, and event payloads without three parallel shapes.

## Decision

1. Add **`ProductSnapshot`** in `shopizer-api-contracts` as the canonical catalog read projection.
2. **`ProductIndexPayload` remains** for HTTP index API backward compatibility but becomes a **thin projection** of `ProductSnapshot` (builder produces snapshot first, then maps to payload).
3. Bump default **`schemaVersion` to 2** on index payloads when snapshot fields are populated; `search-service` accepts v1 and v2 during transition.
4. **`ProductIndexPayloadBuilder`** (monolith) refactored to build `ProductSnapshot` internally.

## Alternatives considered

### Alternative 1: Rename ProductIndexPayload to ProductSnapshot in place

- **Pros:** One type name.
- **Cons:** Breaks Wave 2 Pact and deployed search-service consumers immediately.
- **Rejected:** Prefer additive evolution.

### Alternative 2: Keep ProductIndexPayload forever; add separate ProductSnapshot

- **Pros:** Zero index API change.
- **Cons:** Duplicate field maintenance; violates DRY for Wave 4 catalog read.
- **Rejected:** Single canonical snapshot with adapter to legacy payload.

### Alternative 3: Full CQRS event stream now

- **Pros:** Future-proof for Kafka.
- **Cons:** YAGNI — no broker in Wave 3 (ADR-005 sibling).
- **Rejected:** Snapshot DTO only; events reuse snapshot serialization later.

## Consequences

### Positive

- One builder path from JPA `Product` → snapshot → index/search/catalog consumers.
- Closes AD-009 technical debt incrementally.
- Pact can version on `schemaVersion`.

### Negative

- Temporary dual types in contracts package until Wave 4 deprecates payload-only path.
- search-service must handle v1 documents already indexed.

## Implementation notes

- Package: `com.salesmanager.contracts.catalog.ProductSnapshot`
- Do not import JPA in contracts; nested types are plain DTOs (`ProductSnapshotVariant`, etc.).
- MapStruct mappers in `sm-shop` or `sm-core`.
