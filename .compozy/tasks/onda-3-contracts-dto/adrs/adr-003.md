# ADR-003: Migração facade faseada para MerchantStoreId e LanguageCode

## Status

Aceito

## Data

2026-07-26

## Contexto

Blocker B-001: 20+ interfaces facade em `sm-shop-model` passam entidades JPA `MerchantStore` e `Language`. `AbstractDataPopulator` está hard-wired com os mesmos tipos. ~450 call sites usam `MerchantStoreArgumentResolver`. Uma substituição big-bang tocaria a maior parte de `sm-shop` e arriscaria regressões da Onda 2.

A Onda 3 deve **iniciar** a migração sem completar todas as 76 facades — facades de catálogo e customer são escopo da Onda 4.

## Decisão

1. Introduzir **`MerchantStoreId`** (wrapper de string de store code) e **`LanguageCode`** (wrapper de código ISO) em `shopizer-api-contracts`.
2. **Fase 1 (Onda 3):** Migrar assinaturas em facades adjacentes ao checkout e search:
   - `OrderFacade`, `ShoppingCartFacade`, `SearchFacade`, `ShippingFacade`
   - `CategoryFacade`, `ProductCommonFacade` (caminhos de leitura usados por checkout/search)
3. Fornecer **`TenantEntityBridge`** em `sm-shop` (ou `sm-core`) para hidratar entidades a partir de códigos para chamadas de serviço in-process — **não** no JAR de contracts.
4. Adicionar **overload** em `AbstractDataPopulator`: `populate(source, MerchantStoreId storeId, LanguageCode lang)` defaultando para hidratação via bridge.
5. **Fase 2–3 (Ondas 4–6):** Facades restantes conforme plano publicado (`FAC-06`).
6. **`MerchantStoreArgumentResolver` inalterado** na Onda 3 — ainda resolve entidade para controllers; facades recebem value types convertidos na fronteira.

## Alternativas consideradas

### Alternativa 1: Big-bang em todas as 76 facades

- **Rejeitada:** Diff ilimitado; bloqueia timebox da Onda 3.

### Alternativa 2: Apenas novos métodos; manter métodos de entidade para sempre

- **Rejeitada:** Perpetua B-001; dobra superfície de API.

### Alternativa 3: Códigos string sem value types

- **Rejeitada:** Obsessão por primitivos; sem validação; fácil trocar ordem store/lang.

## Consequências

### Positivas

- Caminho P1 checkout sem entidade na fronteira **interface** facade.
- Adapters HTTP em Onda 4+ passam códigos naturalmente.
- Correções de compilação incrementais por facade.

### Negativas

- Camada bridge temporária e overloads duplos de populator.
- Algum código interno ainda hidrata entidades — documentar como débito técnico até Onda 6.

## Notas de implementação

- Value types: imutáveis, `equals`/`hashCode` no código, `toString` para logs.
- Teste ArchUnit (tail Onda 3): novos métodos facade não devem adicionar parâmetros `MerchantStore`.
