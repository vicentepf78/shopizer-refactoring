# ADR-003: ProductSnapshot como contrato canônico cross-service de produto

## Status

Aceito

## Data

2026-07-26

## Contexto

A Onda 2 introduziu `ProductIndexPayload` intermediário (schemaVersion 1) para extrair busca antes dos contratos completos de produto (STATE.md AD-009). A Onda 3 entrega `ProductSnapshot` como DTO sistêmico para leituras cross-service de produto. A extração de catálogo da Onda 4 e a indexação de busca devem convergir em **um contrato** para evitar builders duplos e drift de pact.

## Decisão

- **`ProductSnapshot` schemaVersion 2** é o DTO canônico de integração de produto em `shopizer-api-contracts`.
- `catalog-service` expõe API HTTP interna de snapshot retornando v2.
- `ProductSnapshotBuilder` do monólito substitui `ProductIndexPayloadBuilder` para indexação de busca.
- `search-service` aceita v2; v1 suportado temporariamente durante migração, depois deprecado.

## Alternativas consideradas

### Alternativa 1: Manter ProductIndexPayload para sempre

- **Prós:** Sem trabalho de migração.
- **Contras:** Duplica investimento da Onda 3; catalog-service e search divergem.
- **Rejeitada:** Pré-requisito da Onda 3 entrega explicitamente ProductSnapshot.

### Alternativa 2: catalog-service constrói snapshots apenas via grafo JPA internamente

- **Prós:** Localização única do builder.
- **Contras:** Monólito ainda precisa de snapshots para eventos quando writes permanecem locais; acopla indexação à disponibilidade do catalog-service.
- **Rejeitada:** Builder do monólito permanece para eventos no lado write; snapshot HTTP opcional para verificação.

### Alternativa 3: Event bus com schemas Avro

- **Prós:** Padrão da indústria em escala.
- **Contras:** Sem infra de bus no projeto; YAGNI para Onda 4.
- **Rejeitada:** Padrão HTTP + RestTemplate (AD-005).

## Consequências

### Positivas

- Unifica contrato de índice de busca e leitura de catálogo.
- Habilita módulos futuros de order/shipping a consumir o mesmo snapshot.

### Negativas

- Task de migração para producer e search-service.
- Janela de suporte dual v1/v2 aumenta matriz de testes.

### Riscos

- Drift de campos entre ReadableProduct e ProductSnapshot — mitigado por pact e testes de builder compartilhado.
