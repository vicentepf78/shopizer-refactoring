# ADR-002: Catalog read-only extraction first (CQRS phased)

## Status

Accepted

## Date

2026-07-26

## Context

Catalog is the **top upstream domain** in `sm-core` with **10 inbound service references** (order, cart, shipping, search, merchant, reference, and others). Full CRUD extraction would replicate the entire catalog write graph—including inventory, pricing, images, variants, and search events—across a network boundary while admin and batch jobs still need transactional consistency with the monolith.

The master plan states: "API read-heavy first; write remains in monolith temporarily."

## Decision

`catalog-service` owns **storefront and public GET APIs** plus internal `ProductSnapshot` reads. **All private admin product mutations** (POST/PUT/DELETE on product admin APIs) remain in `sm-shop` / `sm-core` for Wave 4. Thin core `sm-catalog-core` extracts **read services and mappers only**.

## Alternatives considered

### Alternative 1: Full catalog CRUD extraction

- **Pros:** Single owner for catalog domain.
- **Cons:** Highest coupling; dual-write risk; blocks on order/cart/inventory orchestration.
- **Rejected:** Score 7/10; afferent 10.

### Alternative 2: Extract only categories (smaller slice)

- **Pros:** Lower risk.
- **Cons:** Product reads are primary traffic; incomplete validation of ProductSnapshot.
- **Rejected:** Insufficient value; product read is the main goal.

### Alternative 3: Read replicas / DB views only

- **Pros:** No service extraction.
- **Cons:** Does not validate Strangler pattern for catalog; does not deploy independent runtime.
- **Rejected:** Does not meet wave goals.

## Consequences

### Positive

- Reduces Wave 4 blast radius.
- Storefront scale path independent of admin write path.
- Prepares for future write extraction with snapshot contract already in place.

### Negative

- Split brain: monolith writes DB rows catalog-service reads (acceptable with shared schema AD-022).
- Two codepaths for product logic until write migration.

### Risks

- Stale reads after admin write — mitigated by shared DB + short TTL cache optional; search index via snapshot producer.

## Implementation notes

- Requirement AD-020 enforced in Strangler wiring tests (T30).
- Admin `ProductApi` private methods never delegate HTTP.
